# 免费部署检查清单

这份清单用于在不增加付费服务的前提下，检查项目能否稳定部署和运行。

## 每次发布前

1. 执行 `npm run lint`。
2. 执行 `npm run build`。
3. 确认没有把 Token、数据库密码、OAuth 密钥写进代码。
4. 确认数据库变更不会删除生产数据。
5. 涉及订单、授权、支付时必须人工复核。

## Vercel 免费部署

1. GitHub 推送到 `main` 后自动触发 Vercel 部署。
2. 部署状态可以在后台“免费看板”查看。
3. 如果看板显示部署中，等待 Vercel 完成后再验收。
4. 如果看板显示部署失败，进入 Vercel 部署详情查看日志。
5. 如果 GitHub 状态长时间不更新，直接以 Vercel 后台为准。

## 人工确认上线

如果希望“AI 改完先出日志，管理员再决定是否上线”，可以使用后台“免费看板”的 AI 自动迭代实验区：

1. 先开启实验开关。
2. 点击“触发一次巡检”，让系统写入自动巡检记录。
3. AI 完成修改后，必须提供修改文件、优化内容、验证结果。
4. 管理员确认日志无风险后，再点击“我确认，可以上线”。
5. 未配置 `VERCEL_DEPLOY_HOOK_URL` 时，按钮只记录确认日志；配置后会尝试触发 Vercel Deploy Hook。

## 必要环境变量

这些变量不要提交到 GitHub，只放在 Vercel 环境变量里：

1. `DATABASE_URL`
2. `JWT_SECRET`
3. `NEXT_PUBLIC_APP_URL`
4. `GITHUB_CLIENT_ID`
5. `GITHUB_CLIENT_SECRET`
6. `VERCEL_DEPLOY_HOOK_URL`（可选，用于管理员确认后手动触发部署）
7. 邮件服务相关配置
8. 其他 OAuth 或第三方服务密钥

## 免费额度观察

后台路径：`/admin/free-dashboard`

需要重点看：

1. 函数调用是否超过 70%。
2. 页面/API 请求是否超过 70%。
3. 计算时间是否超过 70%。
4. 流量是否超过 70%。
5. 是否有大量待处理评论、举报、订单。

## 超过 70% 时

1. 先看“用量监控”里的热门路由。
2. 优化请求最多的页面或 API。
3. 减少重复轮询。
4. 压缩图片和静态资源。
5. 暂缓新增高消耗功能。

## 超过 90% 时

1. 先停止非必要新功能开发。
2. 检查是否有异常刷接口。
3. 检查中间件和 API 是否重复记录数据。
4. 必要时临时关闭高消耗功能。
5. 仍不够用时再考虑付费升级。

## 免费监控方案

当前使用项目内置监控：

1. `/admin/free-dashboard` 看整体状态。
2. `/admin/monitoring` 看详细用量和热门路由。
3. Vercel 后台看部署日志。
4. GitHub 提交状态看部署是否回写。

暂不接入付费监控，除非出现频繁线上故障。
