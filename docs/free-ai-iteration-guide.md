# 免费 AI 迭代规则

这份文档用于约束项目后续如何尽量免费地交给 AI 辅助更新。目标不是完全无人值守，而是让 AI 承担重复开发工作，同时避免误删数据、泄露密钥、产生额外费用。

## 免费优先原则

1. 代码托管使用 GitHub 免费仓库。
2. 部署使用 Vercel 免费额度。
3. 数据库优先使用 Neon、Supabase 或其他 PostgreSQL 免费额度。
4. 监控优先使用项目内置后台看板，不先接入付费监控。
5. AI 迭代采用“用户提出需求，AI 修改代码，构建检查，推送部署”的方式。
6. 不默认启用 24 小时自动 AI 巡检，因为这通常会消耗模型额度或平台费用。

## AI 可以直接做

1. 修复普通页面白屏、接口报错、样式错位。
2. 新增不涉及真实扣费和生产数据破坏的小功能。
3. 优化后台页面、表单、列表、搜索、筛选。
4. 补充文档、Issue 模板、部署说明。
5. 执行 `npm run lint` 和 `npm run build` 做基础检查。
6. 提交代码并推送到 GitHub。
7. 自动优化免费订单、免费授权、普通用户权限和后台管理流程。

## 必须人工确认

1. 数据库结构变更，尤其是删除字段、删除表、批量修改数据。
2. 真实支付、扣款、退款、外部计费服务相关逻辑。
3. GitHub Token、数据库密码、OAuth 密钥、Vercel Token。
4. 任何会产生付费资源的操作。
5. 自动合并到生产分支之外的新发布流程。

## 推荐迭代流程

1. 在 GitHub Issue 或对话里写清需求。
2. AI 按需求修改代码。
3. AI 本地执行 `npm run lint` 和 `npm run build`。
4. AI 提交并推送。
5. Vercel 自动部署。
6. 管理员打开后台“免费看板”查看部署状态、免费额度和待办事项。
7. 如果部署失败，先看 Vercel 日志，再让 AI 修复。

## 后台自动迭代实验

后台路径：`/admin/free-dashboard`

“AI 自动迭代实验”区域提供三个动作：

1. 开启实验开关：允许后台记录自动巡检请求。
2. 提交迭代请求：写入操作日志，要求 AI 后续说明“改了哪里、优化了什么、验证结果”。
3. 我确认，可以上线：由管理员明确记录上线确认；如果配置了 `VERCEL_DEPLOY_HOOK_URL`，会尝试触发 Vercel 部署钩子。

这个能力默认是半自动：AI 可以改代码、跑检查、输出日志，但上线动作要由管理员确认。因为本项目是开源免费项目，免费订单、免费授权、普通权限和后台流程可以进入自动迭代；真正需要拦住的是密钥泄露、生产数据删除、破坏性数据库变更、真实支付或外部计费。

注意：后台页面本身不会凭空拥有“写代码的 AI”。现在默认已接入“站内日志迭代队列”，点击按钮会记录一条迭代请求；如果配置了 `GITHUB_TOKEN`，会升级为 GitHub Issue 队列，并由 GitHub Actions 里的免费 AI 执行器尝试生成 PR；如果配置了 `AI_ITERATION_WEBHOOK_URL`，则优先交给你自己的外部 AI 执行器。

## 真正自动执行需要什么

如果要让后台按钮真的触发 AI 自动改代码，需要准备：

1. `AI_ITERATION_WEBHOOK_URL`：你的 AI 代码执行服务地址。
2. `GITHUB_TOKEN`：允许创建 Issue 的 Token；可在后台“安全设置 → GitHub API Token”里保存，也可放在 Vercel 环境变量里。使用 GitHub 免费执行器时，后台提交 Issue 后会触发 `.github/workflows/free-ai-issue-executor.yml`。
3. 执行器能力：GitHub Actions 会调用 GitHub Models 读 Issue、改代码、运行 `npm run lint` 和 `npm run build`、提交分支并创建 PR。
4. 安全限制：免费订单、免费授权和普通权限逻辑可以自动改；真实支付、密钥、生产数据删除和破坏性数据库变更默认不能自动改。

当前执行模式：

1. 只配置网站本身：站内日志迭代队列。
2. 配置 `GITHUB_TOKEN`：GitHub Issue + 免费 AI 执行器。
3. 配置 `AI_ITERATION_WEBHOOK_URL`：外部 AI 执行器。

## GitHub 自动合并

仓库已补充 GitHub 免费自动化配置，详见 `docs/github-automation-guide.md`。

这部分可以做到比较彻底的自动化：

1. Dependabot 自动提交依赖更新 PR。
2. PR 自动执行 lint 和 build。
3. 小版本和补丁更新自动合并。
4. 大版本更新保留人工确认。

这适合依赖维护；业务功能会进入站内队列、GitHub Issue + 免费 AI 执行器，或交给外部 AI 执行器。免费执行器会自动生成 PR，但合并前仍建议管理员看一眼改动。

建议每次 AI 完成后输出这三类日志：

1. 修改位置：列出新增或修改的文件。
2. 优化内容：说明解决了什么问题、为什么这样改。
3. 验证结果：说明 `npm run lint`、`npm run build` 是否通过，以及是否已推送。

## 需求写法

建议每个需求都包含这些信息：

1. 要改哪个页面或功能。
2. 当前哪里不好用。
3. 想要变成什么样。
4. 是否涉及数据库。
5. 是否涉及免费订单、免费授权、真实支付或外部计费。
6. 是否必须免费实现。

## 免费看板用途

后台路径：`/admin/free-dashboard`

这个页面用于快速看懂：

1. 网站整体是否正常。
2. Vercel 部署是否成功或正在部署。
3. 免费额度是否接近上限。
4. 有多少评论、举报、订单需要处理。
5. 当前最应该做什么。

## 不建议的自动化

1. 不建议 AI 自动改完直接上线所有功能。
2. 不建议把长期有效的高权限 Token 发给 AI。
3. 不建议在没有备份的情况下让 AI 自动迁移数据库。
4. 不建议为了“自动”接入一堆付费服务。

## 当前优先级

1. 保持部署稳定。
2. 保持免费额度可控。
3. 先优化后台可用性。
4. 再逐步完善论坛、订单、授权、用户体系。
5. 最后再考虑更复杂的自动化。
