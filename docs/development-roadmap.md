## 一、OAuth 授权服务（当前阶段）

> **现状**：数据模型 `OAuthApp`、`OAuthAuthorizationCode`、`OAuthAccessToken` 已在 `prisma/schema.prisma` 中定义完成，需补齐 API 端点、授权页面、后台管理与接入文档。

|------|------|--------|----------|

| 1.2 | 授权端点 /api/oauth/authorize | P0 | 3 人日 |
| 1.3 | Token 端点 /api/oauth/token | P0 | 2 人日 |
| 1.4 | 用户信息端点 /api/oauth/userinfo | P0 | 1 人日 |

### 1.1 OAuth 应用管理（后台 CRUD）

**优先级**：P0 ｜ **预估工时**：2 人日

**功能描述**

在管理后台提供第三方 OAuth 应用的注册、查看、编辑、启停与删除能力，生成 `client_id` 与 `client_secret`，维护回调地址白名单。

**技术要点**

- 复用已定义的 `OAuthApp` 模型；后台页面建议新增 `app/admin/oauth/apps/page.tsx`，API 路由 `app/api/admin/oauth/apps/route.ts` 与 `[id]/route.ts`。
- `clientId` 使用 `crypto.randomBytes(16).toString('hex')` 生成；`clientSecret` 生成后**加密存储**（联动「敏感数据加密存储」模块），仅在创建时明文回显一次。
- `redirectUris` 以 JSON 数组字符串存储，保存前校验：仅允许 `https` 与 `http://localhost`，避免开放重定向。
- 复用 `lib/auth.ts` 中的 `adminAuth` 中间件做管理员鉴权；操作记录写入 `OperationLog`。
- 支持应用启停（`status: active | disabled`），禁用后授权与令牌端点立即拒绝。

### 1.2 授权端点 /api/oauth/authorize

**优先级**：P0 ｜ **预估工时**：3 人日

**功能描述**

实现 OAuth 2.0 Authorization Code 流程的授权入口，校验请求参数与客户端合法性，引导用户完成授权同意后下发一次性授权码。

**技术要点**

- 新增 `app/api/oauth/authorize/route.ts`，处理 `GET` 请求，参数：`response_type=code`、`client_id`、`redirect_uri`、`scope`、`state`（必填，防 CSRF）。
- 校验链路：`client_id` 存在且 `active` → `redirect_uri` 命中白名单 → `response_type` 合法 → `state` 非空。
- 用户未登录时 302 跳转 `/login?return_to=<原 URL 编码>`，登录后回跳继续授权流程。
- 用户同意后写入 `OAuthAuthorizationCode`：有效期 10 分钟、`used=false`、绑定 `redirectUri` 与 `scope`，随即 302 重定向回 `redirect_uri?code=xxx&state=xxx`。
- `state` 校验建议结合短期 cookie 或服务端缓存做绑定校验，防止伪造。
- 用户拒绝授权时重定向携带 `error=access_denied`，不得直接抛 500。

### 1.3 Token 端点 /api/oauth/token

**优先级**：P0 ｜ **预估工时**：2 人日

**功能描述**

接收授权码换取访问令牌（access_token），校验授权码与客户端凭据的合法性后签发令牌。

**技术要点**

- 新增 `app/api/oauth/token/route.ts`，处理 `POST`（`application/x-www-form-urlencoded`），支持 `grant_type=authorization_code`，可选扩展 `refresh_token`。
- 校验：`code` 存在且未过期且 `used=false`、`client_id`+`client_secret` 匹配、`redirect_uri` 与授权时一致；任一失败返回标准 OAuth 错误码（`invalid_grant` / `invalid_client`）。
- 成功后立即将 `code.used` 置 `true`，防止授权码重放攻击。
- 签发 `OAuthAccessToken`：令牌可选用 opaque 随机串或 JWT（复用 `jsonwebtoken`），`expiresAt` 默认 2 小时，返回 `access_token`、`token_type=Bearer`、`expires_in`、`scope`。
- 强制 HTTPS 校验；该端点必须叠加限流（联动 2.1 接口限流）。
- 仅允许 `application/x-www-form-urlencoded`，禁用 CORS 跨域，避免凭据泄漏。

### 1.4 用户信息端点 /api/oauth/userinfo

**优先级**：P0 ｜ **预估工时**：1 人日

**功能描述**

供第三方应用凭 access_token 获取当前授权用户的基础信息，按 scope 控制返回字段。

**技术要点**

- 新增 `app/api/oauth/userinfo/route.ts`，处理 `GET`，从 `Authorization: Bearer <token>` 解析并查询 `OAuthAccessToken`。
- 校验令牌有效未过期，按 `scope` 返回对应 claims：`openid`（sub）、`profile`（username/avatar/bio）、`email`（email）。
- 返回结构与 OIDC UserInfo 对齐，便于后续向 OIDC 演进。
- 令牌使用可记录访问日志（应用维度），便于接入方排障与审计。

### 1.5 用户授权同意页 /oauth/authorize

**优先级**：P0 ｜ **预估工时**：2 人日

**功能描述**

面向终端用户的授权确认页面，展示申请授权的应用信息与权限范围，提供「同意 / 拒绝」操作。

**技术要点**

- 新增 `app/oauth/authorize/page.tsx`（页面），与 API 端点 `/api/oauth/authorize` 路径前缀区分（API 在 `/api/` 下）。
- 页面读取 URL 参数渲染：应用名称、Logo、主页链接、请求 `scope` 列表、回调地址脱敏展示。
- 「同意/拒绝」表单 `POST` 至授权端点，复用 1.2 的发码逻辑；提交时校验 `state`。
- 未登录用户重定向 `/login`；登录态读取复用 `getUserFromRequest`。
- 页面需防点击劫持：设置 `X-Frame-Options: DENY` / CSP `frame-ancestors 'none'`。
- 适配暗黑模式与移动端（联动第三章），保持与站点整体风格一致。

### 1.6 接入文档编写

**优先级**：P1 ｜ **预估工时**：1 人日

**功能描述**

面向第三方接入方的完整技术文档，降低接入成本并规范错误处理。

**技术要点**

- 新增 `docs/oauth-integration.md`，内容覆盖：应用注册流程、授权码流程时序图、各端点请求/响应示例、scope 说明、错误码表、`curl` 与 JS 示例、安全注意事项。
- 文档随接口变更同步维护；建议在后台「OAuth 应用管理」页提供文档直达链接。
- 可附带最小可运行示例仓库链接，便于快速联调。

## 二、安全增强

> **阶段定位**：在 OAuth 上线的同时补齐通用安全能力，满足合规与稳定运行要求。

| 序号 | 功能 | 优先级 | 预估工时 |
|------|------|--------|----------|
| 2.1 | 接口限流 (Rate Limiting) | P0 | 2 人日 |
| 2.2 | CSRF 防护 | P0 | 2 人日 |
| 2.3 | XSS 过滤 | P1 | 1 人日 |
| 2.4 | 敏感数据加密存储 | P0 | 2 人日 |

### 2.1 接口限流 (Rate Limiting)

**优先级**：P0 ｜ **预估工时**：2 人日

**功能描述**

对登录、注册、OAuth Token、发帖、评论等敏感与高消耗接口实施速率限制，防止暴力破解与滥用。

**技术要点**

- 基于内存或 Redis 实现（单实例可先用 `Map` + 滑动窗口；多实例上 Redis），按 `IP + 路由` 维度计数。
- 分级策略：登录/Token 端点 10 次/分钟；发帖 5 次/分钟；通用 API 60 次/分钟；超限返回 `429` 并带 `Retry-After`。
- 封装为可复用中间件 `lib/rate-limit.ts`，在 Route Handler 入口调用；可结合 `middleware.ts` 做边缘限流。
- OAuth Token 端点必须限流（防授权码/凭据暴力枚举），与 1.3 联动。

### 2.2 CSRF 防护

**优先级**：P0 ｜ **预估工时**：2 人日

**功能描述**

防止跨站请求伪造，覆盖表单提交与状态变更类接口，OAuth `state` 参数纳入统一校验体系。

**技术要点**

- 对浏览器侧状态变更请求采用 **双提交 Cookie** 模式：服务端下发 `csrf_token`，前端请求头回传同名令牌并校验一致性。
- OAuth 授权流程的 `state` 强制必填并校验，未通过返回错误页（联动 1.2）。
- 关键接口校验 `Origin` / `Referer`，拒绝跨站来源。
- 复用现有 httpOnly cookie 体系，注意与 GitHub OAuth 回调、JWT cookie 的协同。

### 2.3 XSS 过滤

**优先级**：P1 ｜ **预估工时**：1 人日

**功能描述**

对用户输入与渲染内容做净化，防止存储型与反射型 XSS。

**技术要点**

- 帖子/评论 Markdown 渲染统一走 `react-markdown` + `remark-gfm`（项目已集成），禁用 raw HTML；如需允许部分标签，接入 `rehype-sanitize` 做白名单过滤。
- 用户昵称、简介等纯文本字段入库前转义或限制字符集；列表页摘要渲染避免 `dangerouslySetInnerHTML`。
- 设置 CSP 响应头，限制脚本来源与内联脚本；配合 nonce 进一步收敛。
- 输出编码统一走 React 自动转义，禁止手动拼接 HTML。

### 2.4 敏感数据加密存储

**优先级**：P0 ｜ **预估工时**：2 人日

**功能描述**

对 OAuth `client_secret`、Resend API Key、第三方凭据等敏感字段加密后入库，明文仅在内存中使用。

**技术要点**

- 引入对称加密（`crypto` AES-256-GCM），密钥由环境变量 `ENCRYPTION_KEY` 注入，禁止硬编码。
- 封装 `lib/crypto.ts`：`encrypt(plain)` / `decrypt(cipher)` 工具，统一带 IV 与认证标签。
- 改造点：`OAuthApp.clientSecret`（联动 1.1）、`SystemSetting` 中的 Resend API Key、后续接入的第三方密钥。
- 加密字段在后台展示时做脱敏（如 `••••••`），仅支持「重新生成」而非「查看明文」。

### 2.5 操作审计日志增强

**优先级**：P1 ｜ **预估工时**：2 人日

**功能描述**

在现有 `OperationLog` 基础上扩展审计维度，覆盖 OAuth 授权、令牌签发、敏感配置变更等高风险动作。

**技术要点**

- 复用 `OperationLog` 模型，扩展 `action` 枚举集合：`oauth_authorize`、`oauth_token_issue`、`oauth_app_create/update/delete`、`security_config_update` 等。
- 关键操作补充 `User-Agent`、`referer`、`result（success/fail）` 字段（模型需小幅迁移）。
- 后台 `/admin/users/logs` 增加按 `action`、时间范围、用户、结果筛选；支持导出 CSV。
- 对失败操作（如 Token 校验失败、限流触发）单独标记，便于安全运营分析。

### 3.1 暗黑模式

**优先级**：P1 ｜ **预估工时**：2 人日

**功能描述**

提供明/暗主题切换，记忆用户偏好并跟随系统设置。

**技术要点**

- 基于 Tailwind `darkMode: 'class'`，在 `tailwind.config.js` 切换为 class 策略；全局色板用 CSS 变量统一管理。
- 主题状态可用 Zustand 持久化（项目已集成 zustand），并在 `<html>` 注入 class，避免首屏闪烁（FOUC）可结合内联脚本提前设置。
- 复用后台已有的「外观设置」页（`app/admin/settings/appearance/page.tsx`）作为站点默认主题配置入口。
- 全量排查组件硬编码颜色，统一替换为语义化 class（`bg-background`、`text-foreground` 等）。

### 3.2 多语言支持 (i18n)

**优先级**：P2 ｜ **预估工时**：5 人日

**功能描述**

支持中英文（可扩展）多语言，覆盖界面文案与邮件模板。

**技术要点**

- App Router 下采用 `next-intl` 或基于路由前缀（`/zh`、`/en`）的方案；评估是否需要 URL 前缀，无前缀则用 cookie + Accept-Language 协商。
- 文案抽取为 JSON 资源文件按模块组织；用户内容（帖子/协议）仍以原文存储，不在翻译范围。
- 邮件模板与通知文案同步国际化；后台协议文档可考虑多语言版本（`SystemSetting` 扩展 key 后缀）。
- 切换器放 Header，偏好持久化；SEO 配合 `hreflang` 标注。

### 3.3 PWA 支持

**优先级**：P2 ｜ **预估工时**：2 人日

**功能描述**

将站点改造为可安装、可离线访问的渐进式 Web 应用。

**技术要点**

- 使用 `next-pwa` 或手写 Service Worker；缓存策略区分：静态资源 cache-first、API stale-while-revalidate、认证接口不缓存。
- 提供 `manifest.json`（图标、主题色、启动页），配合暗黑模式主题色联动。
- 离线场景提供降级页与「已离线」提示；论坛列表支持离线阅读最近缓存。
- 注意 Service Worker 与 httpOnly cookie / Bearer token 的兼容，避免缓存鉴权响应。

### 3.4 移动端适配优化

**优先级**：P1 ｜ **预估工时**：3 人日

**功能描述**

系统性优化小屏体验，覆盖导航、论坛、后台与 OAuth 授权页。

**技术要点**

- 排查全站断点：Header 折叠为汉堡菜单，论坛列表/详情单栏布局，表格横向滚动或卡片化。
- 触控目标不小于 44px；表单输入触发合适键盘类型；禁用 iOS 缩放。
- 后台管理页适配平板（移动端只读优先，写操作引导至桌面）；OAuth 同意页移动端单独验收（联动 1.5）。
- 新增移动端视觉走查清单，纳入提测标准。

### 3.5 搜索功能增强（全文检索/搜索建议）

**优先级**：P1 ｜ **预估工时**：4 人日

**功能描述**

在现有 `/search` 基础上升级为全文检索，并提供输入时的搜索建议。

**技术要点**

- PostgreSQL 全文检索：为 `Post.title/content` 建立 `tsvector` 与 GIN 索引，使用 `websearch_to_tsquery` 支持中文需配合 `pg_jieba` 或 `zhparser` 扩展；若扩展不可用，退化为 `ILIKE` + 关键词分词。
- 现有 `app/api/search/route.ts` 扩展为多类型（帖子/工具/用户）聚合搜索，支持高亮与权重排序。
- 搜索建议：前端防抖（300ms）调用轻量建议接口，返回热门词与历史匹配；建议数据可基于近 N 天搜索日志统计。
- 搜索结果分页与缓存（短 TTL），高频词结果可预计算。

## 附录 B：风险提示

- **安全合规**：OAuth 与安全模块（限流/CSRF/加密）强耦合，建议作为 M1 整体交付，避免「端点上线但无防护」。
- **数据库扩展依赖**：全文检索（3.5）依赖 PostgreSQL 中文分词扩展，需提前确认托管环境是否支持 `pg_jieba`/`zhparser`，否则需调整方案。
- **第三方执行环境**：在线代码编辑器（5.1）沙箱安全成本高，建议优先对接第三方执行 API，自建沙箱需独立评估。
- **包体积**：Monaco Editor、i18n 资源、富文本编辑器均显著增加前端体积，需配合动态导入与按需加载。
- **多语言内容**：用户生成内容（帖子/协议）不在 i18n 自动翻译范围，需明确边界避免误解。
